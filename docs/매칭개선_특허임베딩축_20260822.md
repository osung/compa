# 매칭 점수 개선 — 과제 특허 임베딩 축 도입 (2026-08-22)

## 1. 요구사항

> "과제별 특허의 임베딩 벡터와 기업 임베딩 벡터의 유사도 점수를 최종 매칭 점수에
> 반영하려고 해. **유사한 특허가 많은 과제일수록 점수가 높도록** 했으면 좋겠는데"
>
> "특허 유망성도 점수에 포함하면 좋지 않을까?"
>
> "유사하고 유망한 특허가 많을수록 최종 매칭 점수가 높아지도록"

## 2. 기존 점수 체계의 결함

특허를 **건수로만** 셌다. 코퍼스 조건이 "특허 1건 이상"이므로

- 그 특허가 **기업의 기술과 관련이 있는지** 보지 않았다
- 그 특허의 **권리가 살아 있는지** 보지 않았다 — 거절·취하된 특허 1건짜리 과제도 통과한다

보고서는 "기술이전 협의가 가능한 과제"를 추천한다고 쓰는데, 권리가 없는 특허만 가진
과제가 섞여 들어갈 수 있었다. 특허 건수의 LLM 적합도 순위상관은 **+0.045** 로,
사실상 신호가 없었다.

|---|---|---|
| 자기 부모과제 | **0.7785** | 0.8172 |
| 무작위 과제 | 0.5295 | 0.5058 |
| 자기 > 무작위 | **81.6%** | |

같은 공간이다. 특허끼리 무작위 쌍 분포(P50 0.491)와 과제끼리 분포(P50 0.569)도

## 4. 유망성 — 합성 점수를 쓰지 않고 구성요소를 골라 쓴 이유

## 5. 축 설계

### 5.1 질의별 적응 임계값

짧은 키워드 질의는 코퍼스 중심 근처에 놓여 모든 특허와 높은 유사도를 갖는다(hubness).
실측한 P90 이 질의에 따라 **0.379 ~ 0.979** 로 흔들려서 절대 임계값을 쓸 수 없다.
질의마다 백분위로 다시 잡는다.

```
τ_q   = 코퍼스 전체 특허 유사도의 P90
rel_i = max(sim_i − τ_q, 0)          ← 임계 초과분만 인정
```

### 5.2 품질은 더하기가 아니라 곱하기

처음에 사용자가 고른 구성(유사도 0.55 + 권리 0.30 + 최신성 0.15)을 **더하기**로
구현했는데, 실측에서 관련성 신호가 절반으로 깎였다. 권리·최신성은 *기업 적합성*이 아니라
*자산 품질*을 재는 값이라 LLM 적합도와 상관이 없거나 음인데, 가중의 45%를 차지하면서
순위를 흐린 것이다.

| 구성 | 적합도 순위상관(기업내) | 유사특허 개수 단조성 | 권리 변별 |
|---|---|---|---|
| A 더하기 `0.55·유사강도 + 0.30·권리 + 0.15·최신성` | +0.074 | +0.624 | 있음 |
| **B 곱하기 `품질 × 관련성`** | **+0.127** | **+0.947** | **있음** |
| C 품질 무시(관련성만) | +0.129 | +0.947 | 없음 |

개별 신호의 적합도 상관(3,684쌍 · 26개사):

| 신호 | 전체 | 기업내 |
|---|---|---|
| 에너지 E | +0.141 | +0.128 |
| 유사특허 개수 | +0.119 | +0.107 |
| 최고 유사도 | −0.019 | +0.098 |
| **권리상태** | **−0.049** | **−0.037** |
| **최신성** | **−0.017** | **−0.032** |
| 특허 건수(기존) | +0.042 | +0.045 |

B 를 채택했다. 세 계수의 **의미는 그대로 살린다** — 0.55 는 관련성 기본값,
0.30 은 권리 프리미엄, 0.15 는 최신성 프리미엄이다.

### 5.3 최종 식

```
qual_i = 0.55 + 0.30·법적상태_i + 0.15·최신성_i          ∈ [0.55, 1.00]
  → 등록 특허 1건은 취하 특허 1건의 약 1.42배로 세어진다(최신성 평균 0.75 기준)

E_p    = Σ_i rel_i · qual_i        ← 유사하고 · 유망하고 · 많을수록 커진다
e_n    = 1 − exp(−E_p / E_ref),  E_ref = E>0 인 과제의 P95
mx_n   = (max sim − τ)/(1 − τ)

pat_n  = 0.75·e_n + 0.25·mx_n·qual_best
```

- **`1 − exp(−E/E_ref)`** — P95 에서 자르지 않는다. 상한 1.0 에 붙지 않는 포화 곡선이라
  상위 구간에서도 개수 효과가 계속 살아 있다(E=E_ref 에서 0.632, 2배 0.865, 3배 0.950).
- **최고 유사도 항 0.25** — 코퍼스 과제당 특허 **중위 1건**(평균 2.5 · 최대 153)이므로
  에너지만 쓰면 특허 1건짜리 과제가 부당하게 밀린다. 그 항에도 해당 특허의 품질을 곱한다.
- **0점은 정상값** — 질의 유사도 P90 을 넘는 특허가 그 과제에 없다는 뜻이다. 축이
  침묵하고 다른 축이 순위를 정한다.

### 5.4 τ 백분위 선택

| τ | 적합도 상관 | 개수 단조성 | 0점 비율 | 적합도 75+ 행 중 0점 |
|---|---|---|---|---|
| P50 | +0.081 | +0.820 | 12.8% | — |
| P75 | +0.100 | +0.894 | 29.3% | — |
| **P90** | **+0.127** | **+0.947** | **52.3%** | **43.0%** |
| P95 | +0.130 | +0.979 | 68.5% | 61.3% |
| P97 | +0.138 | +0.990 | 78.7% | 72.6% |

P90 을 기본값으로 한다. τ 를 더 올리면 상관은 계속 오르지만 0점 비율이 79%까지 가서
축이 사문화된다(개수 단조성 +0.99 도 대부분의 과제에서 개수가 0/1 이 되며 생기는
겉보기 값이다). `--patsim-tau` 로 바꿀 수 있다.

## 6. 두 단계 모두에 넣는다

```
W_PAT_PRE, W_PAT_RE = 0.20, 0.12
```

1차선정에 넣지 않으면 "유사한 특허가 많은 과제"가 애초에 후보(N_CAND=120)에 들어오지
못해 재랭킹이 손쓸 수 없다. 가중치 합은 코드에서 정규화되므로(`psum`/`wsum`) 실효 비중은

| 단계 | 적합도 | 과제 유사도 | 과제 유망성 | **특허축** |
|---|---|---|---|---|
| 1차선정 | — | 0.625 | 0.208 | **0.167** |
| 재랭킹 | 0.625 | 0.134 | 0.134 | **0.107** |

`--no-patent-axis` 로 이전 점수 체계로 되돌릴 수 있다.

## 8. 검증 항목 (match_meditek_supply.verify)

- 특허축 값 유한 · 0~1 범위
- 유사특허 보유행은 특허축 > 0
- 유사특허 없는 행은 최고유사도가 임계 이하 (0점의 근거 재현)
- 품질계수 0.55~1.00 범위
- 특허권리상태·특허최신성·특허유사강도 0~1 범위
- 유사특허수 ≤ 특허건수
- **유사특허수 ↑ → 특허축 ↑** (기업내 순위상관 > 0) ← 요구사항 직접 검증
- 거절·취하 특허만 매칭된 추천 없음 (권리상태 < 0.2)

## 10. 특허 상태 필터 — 코퍼스 조건 변경

기존 코퍼스 조건은 "특허 1건 이상"이었다. 그런데 거절·취하·포기된 특허는 권리가
성립하지 않았고 소멸된 특허는 권리가 끝났다. 그런 특허만 가진 과제는 기술이전 협의
대상이 될 수 없는데도 통과했다. 조건을 **"출원 계류(공개) 또는 등록 특허 1건 이상"**
으로 바꿨다.

| 상태 | 인정 | `법적상태_score` | 전체 특허 403,024건 중 |
|---|---|---|---|
| 등록 | ○ | 1.00 | 210,411 |
| 공개(출원 계류) | ○ | 0.45 | 42,185 |
| 소멸(만료) | ✕ | 0.55 | 88,675 |
| 거절 | ✕ | 0.10 | 40,819 |
| 취하 | ✕ | 0.05 | 19,064 |
| 포기 | ✕ | 0.05 | 1,869 |

**점수가 아니라 상태명으로 판정해야 한다** — 소멸의 `법적상태_score` 는 0.55 로 공개
(0.45)보다 높지만 권리는 이미 끝났다. `ALIVE_STATES = ("등록", "공개")` 로 상태명을 직접
본다.

세 곳에 같은 규칙을 걸었다.

규모 변화:

| | 전 | 후 |

| 특허 보유 과제(전국) | 201,958 | 156,565 (77.5%) |

- **추천당 특허 2.56 → 4.35건** — 목표대로 특허 실적이 두꺼운 과제가 올라왔다.
- **등록특허 보유 추천 104/130 · 출원 계류만 26/130** — 전건이 살아 있는 권리를 가진다.
- **유사특허 보유 추천 93/130 · 유사특허수 평균 1.45건**
- **유사특허수 ↑ → 특허축 ↑ 기업내 ρ = +0.853** — 요구사항이 산출물에서 성립한다.
- 적합도 평균은 78.4 → 78.6 으로 오히려 올랐다.

### 재랭킹 가중을 0.12 → 0.08 로 낮춘 이유

`w=0.12` 로 두면 축이 **적합도 10점 차이를 뒤집는다**.

```
적합도 10점 = 최종 6.25점        특허축 0.65 차 = 최종 7.0점
```

실측에서 인재양성·기관지원 사업이 적합도 50짜리 추천을 밀어내고 3행 → 8행으로
늘었다((주)레브히트 50/50 → 40/40 등). 기존 연계유형 가중이 의도적으로 "적합도 약
5점 상당의 핸디캡"으로 맞춰져 있으므로 특허축도 같은 수준으로 낮췄다.
1차선정 가중(0.20)은 누가 채점 대상이 되는지만 정하므로 강하게 두어도 무해하다.

## 12. 남은 문제 — 우산형 과제 (별건)

코퍼스에 **인재양성·기관지원류 과제 38건**이 있다. 과제명이 `인공지능대학원지원`,
`지역지능화혁신인재양성`, `경북대학교`, `충북대학교` 같은 것들로, 기술이 아니라 사업·기관
단위 묶음이다. 산하 연구실 특허를 대량 누적해서(최대 153건) 특허축에 유리하다.

특허축 도입으로 3행 → 8행으로 늘었다. K 상한을 두어도 해결되지 않았다:

| K | 적합도 상관 | 우산형/집중형 축 평균비 | 축 상위 30에 든 우산형 |
|---|---|---|---|
| 2 | +0.133 | 1.61 | 3.6 |
| 5 | +0.133 | 1.98 | 4.9 |
| 무제한 | +0.133 | 2.07 | 5.0 |

K 는 신호를 전혀 잃지 않으므로(적합도 상관 +0.133 고정) 병리적 포트폴리오 방어용으로
5 를 유지하되, **근본 해결은 코퍼스에서 우산형 과제를 빼는 것**이다. 다만
(주)비전메디컬 4위 `지역지능화혁신인재양성` 은 LLM 적합도 92, (주)더멘드 5위
`인공지능대학원지원` 은 85 로 — 과제설명문에 실제 연구 내용이 들어 있어 — 일괄 배제가
항상 옳지는 않다. 별건으로 판단이 필요하다.

현재 8행 중 3행은 인투브이에스(주)(적합도 15/20/35)로, 그 기업은 후보풀 자체가 얕아
특허축 도입 전에도 적합도 45/25/20/15 였다(코퍼스 필터를 `--field 전체` 로 넓히는 것이
별도 대안).
